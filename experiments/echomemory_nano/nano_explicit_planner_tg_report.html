EchoMemory Nano: Explicit Planner / Retriever / Composer

这个 nano 的目的不是提高分数，而是把主仓里现在混在 SearchService 里的几件事拆开： Planner 决定 query family，Retriever 决定 graph-first 还是 hybrid，EvidenceComposer 决定怎样把命中的证据组合成回答。

为什么要拆

  • 便于做 clean ablation：到底是 planner 错，还是 retrieval 错，还是 answer composition 错。
  • 便于把 temporal / relational / visual query 分别设计成不同的证据路径。
  • 便于把它画成论文方法图，而不是一大团 SearchService 逻辑。
