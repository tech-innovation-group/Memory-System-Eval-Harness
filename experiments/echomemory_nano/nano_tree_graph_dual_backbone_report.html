EchoMemory Nano: Stream + Temporal Tree + Relation Graph

This nano is designed to explain one concrete upgrade direction for EchoMemory: instead of treating graph memory as a sparse sidecar, use a dual-backbone memory with a temporal tree for chronology and a relation graph for entity / event / image evidence traversal.

What this nano tries to demonstrate

  • Temporal queries should not rely only on flat fact matching.
  • Relational queries should enter through graph entities and event links.
  • Visual evidence should be a first-class memory object, not extra prompt text.
  • messages_persisted is weaker than qa_ready.
  • Tree backbone: coarse-to-fine chronology blocks.
  • Graph backbone: entity / event / fact / image nodes and path expansion.
  • Planner: route by query family instead of one universal retrieval mode.
  • Output: inspectable hits plus readiness state.
