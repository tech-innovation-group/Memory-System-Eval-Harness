EchoMemory Relation Backbone Ablation

这组小实验和 anchored temporal ablation 成对：它只测 relation-heavy questions， 看 tree-only、graph-only、dual-backbone 谁更适合作为 primary backbone。

Cases3
Tree-only0
Graph-only3
Dual-backbone3

Results

Case Query Expected Top Tree-only Graph-only Dual-backbone Note
spouse_relation Who is Gina married to? entity, event tree / no event / yes event / yes Spouse relation should prefer graph entry points rather than chronology blocks.
plan_relation What did Gina plan after leaving Figma? entity, event tree / no event / yes event / yes Plan-after-event is still relation-heavy because it depends on linking plan and departure event.
company_left Which company did Gina leave? event, entity tree / no entity / yes entity / yes Company-of-departure is a relation grounded in a specific event edge.

Interpretation

如果这组结果比 anchored temporal ablation 呈现出相反趋势，那就正好支持 paired claim： temporal questions 应该以 tree 为主，relation-heavy questions 应该以 graph 为主。
