# 六项观测改进与交付边界

本清单对齐用户提供的 `REPORT-IMPROVEMENT-GUIDE.html`，在
`performance_refactor` 基础上继续维护 PR32。它不是实测结果，也不表示六项已完成。

## 已落实的基础

- 同步目标分支的连接管理、有界停止和 Engine 级资源回收修改；同步后必须重新回归，不能沿用旧版本测试数。
- 正式 M4 按 tenant/session/archive 对账，区分非终态确认窗口与宽观察窗口。
  timeout/停止观察不是任务执行失败，重复或孤立记录不覆盖其他证据。
- 容量单项自动记录执行平台的 Git 提交、performance 工作区改动状态、Python 源码指纹。
  六项入口在开始时采集并复用版本，不在结束时重新读取 HEAD 冒充运行版本。
- 报告区分平台基础版本与执行版本。没有 Git 的部署包只提供源码指纹，不猜测 commit。
  历史数据不补填现在的平台版本；服务端 EchoMem 版本仍需要独立运行证据。
- 通用场景超时后若已确认停止，仍持久化真实请求记录及错误，状态保留 TIMEOUT，
  不被 resume 当作已完成。尚未停止的执行仍禁止推进下一场景。

## 六项下一步与所需数据

M3 发压基础已补充 `load.arrival.<task>.scope: per_tenant`：同一租户的
worker 共用自己的限速器，不会把未使用配额转给其他租户。
`rps` 此时表示每租户的计划到达率，整体计划速率为租户数乘以该值；
默认 `global` 的既有含义不变。`start_s` 表示相对运行开始的首次发压时间，
可用于先预热 Search 再开始 Commit。每个启用的任务至少需要每租户一个 worker。
这只是发压基础，不等于实际请求已达到计划速率：worker 忙于等待响应或轮询时仍可能延迟，
正式 M3 已接入计划/实际到达差、测量窗口和窗口外排空，不能仅凭配置宣布公平。
`end_s` 截止后不再启动新事务，已有事务在运行总截止时间前继续观察。
仍需用新版完成真实服务实测，旧洪泛数据不会自动变成新版 M3 结果。

## 尽早给出数据，不缩减目标

1. 先一次性检查服务/真实模型/独立租户/故障控制/4U8G；预检失败直接给出阻塞证据，不长时间盲等。
2. 同一版本、配置、语料的记忆只准备一次；复用前验证各租户真实可召回。不能复用其他版本的验证结论。
3. 调整执行编排，先完成可界定时长的 M2–M6 并阶段性发布报告，再追加 M1 容量阶梯。
   当前入口已在容量阶梯前写入阶段报告；M1 中断时保留已取得数据并明确标记未完成。
   进入 M1 前再次检查服务就绪，避免故障撤销失败后继续发压。
4. M6 采样持续到 M1 阶梯结束；阶段报告只包含当时已采集的数据，中断时保存最终快照。
   是否覆盖容量阶段新建的每个租户/Lane 仍须检查实际矩阵，持续采样不等于全租户覆盖。
   互相干扰的 M2 故障、M3 公平性和 M4 洪泛串行，不能为缩短时间混跑。
5. 每阶段记录计划时长、实际时长、轮询/排空/恢复耗时。为观察设截止时间，超时保留未完成任务；
   截止不是“服务最大容量”的证明。默认不启用 soak。
6. 快速矩阵必须覆盖规定的目标/故障/拓扑，短窗口低样本量单列；完整容量、稳态和恢复结论需对应证据。
   不承诺仅缩短采样窗口就能证明全部六项完成。

## 对指南示例的必要修正

### 回归风险记录

2026-09-08 正式 M3 的 `57e64c5` 运行发现协议适配缺陷：真实接口返回
`{"status": {"status": "completed"}}`，原通用场景只解析顶层字符串。
56 个原始 202 任务后续只读确认全部 completed，但旧轮询产生 46,200 次请求，
其中 5,789 次 HTTP 错误，干扰了负载。该轮不能作为有效 M3 性能结论；不能将事后终态回填历史完成时间。
修复统一复用 EchoMem 的 `status_from`；回归同时覆盖嵌套 pending/completed/failed。
成功轮询没有识别到任何状态时，报告明确标记协议证据缺口，不能再称为完整实测。

本地 macOS 回归中，`test_request_aborts_on_interrupt_while_body_stalled` 曾在完整运行及单独复跑中失败，
随后带线程栈诊断连续五次通过。尚未确认根因，不能因重跑变绿就声明已修复。
该测试验证停止时阻塞响应体能及时退出；保留原断言，若实测出现 worker 无法停止，应保留现场、禁止推进下一场景。
随后一次完整回归有 699 项与 13 项子测试通过，但同组的
`test_request_aborts_on_interrupt_when_connection_close_detaches_socket` 失败；
因此这类连接中断风险仍未关闭，不能对外声称全量回归始终通过。

- 租户零完成是有意义的结果，保留在 Jain 分母；洪泛与稳态用途不同，而不是差结果就无效。
- `elapsed % 30 < 1` 可能在一秒内重复提交很多次。必须预先编排每租户的唯一周期事件，记录计划与实际提交时间。
- 不预设公平性“应该成功率高/P95接近”才有效，不将性能不佳隐藏为缺数据。
- JSON 数值缺失使用 `null`，由 HTML 显示“未采集”，不能把字符串塞进数值列参与计算。
- EchoMem 版本接口要先验证真实支持，不能照搬示例中的 `/api/version`。容器名、镜像 ID、源码 commit 各自说明证据范围。
- 图表读与表格相同的规范化数据，不写死指南示例数字；离线 HTML 不依赖外部 CDN。
- 筛选默认显示全部错误；筛选不修改总分母和总体结论，导出需保留当前筛选范围说明。
