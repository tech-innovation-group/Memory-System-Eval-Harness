EchoMemory 召回条数说明

说明 LoCoMo QA 里“召回多少条记忆”到底由什么决定，以及为什么 top_k=30 不等于一定会注入 30 条。

搜索上限 top_k
每次 search 的 max_results，也是最终 selected 的上限。
当前单题 run 24 / 30
最新单题 run 的 selected_count=24，不是 30。
真正注入 受预算裁剪
最终还要再过 user / agent memory budget。

核心结论

“召回多少条记忆”分三层：先搜索候选，再筛成 selected，最后再裁成真正注入给 LLM 的 memory block。
  • top_k 决定的是最终保留条数的上限，不是一定会注入多少条。
  • score_threshold、去重、重排规则，会让最终 selected_count 小于 top_k。
  • 真正注入给模型的内容，还要再经过 user_memory_budget_chars 和 agent_memory_budget_chars 裁剪。

三层计数

阶段 控制项 实际含义
1. 搜索候选 top_k + sdk.search(... max_results=top_k) 每个 query variant 最多拿多少条候选。
2. 最终 selected score_threshold + dedup + rank_hits_for_prompt() 合并、过滤、重排后真正留下的 recall 条数。这个值会写进 selected_count。
3. Prompt 注入 user_memory_budget_chars + agent_memory_budget_chars selected 里的内容再被格式化和截断，最后喂给 LLM 的不一定是全部 selected。
