EchoMemory QA

打印检索到的记忆：逻辑整理与参考代码

这份文档只整理 EchoMemory 评测中“把检索到的记忆打印到实时日志”这条逻辑链，重点是触发点、辅助函数、输出格式和参考代码。

核心结论

已实现
实现文件 scripts/echomemory_memory_qa.py
触发时机 每题检索完成后
输出内容 候选记忆 top 5 摘要
影响面 只增 stdout 日志

逻辑链路

  1. 入口函数：answer_question() 是 EchoMemory QA 每题处理的主入口。
  2. 检索阶段：在 qa_memory_injection 开启时，调用 echomemory_retrieve(args, sdk, query) 拉取候选记忆。
  3. 后处理阶段：检索结果会继续经过 inject_segment_raw_readback()，把需要的 segment raw readback 注入进来。
  4. 日志阶段：在缓存、prompt 构造、模型回答之前，调用 log_retrieved_memory_preview() 把当前题命中的候选记忆打印到 stdout。
  5. artifact 保持原样：完整检索结果仍然通过 write_recall_log() 写入 qNNN.recall.json，并写入 CSV 的 relevant_memory 字段。

参考代码 1：日志辅助函数

def log_retrieved_memory_preview(
    job: benchmark_adapter.Job,
    hits: list[dict[str, Any]],
    *,
    question_no: int | None = None,
    max_items: int = 5,
    preview_chars: int = 220,
) -> None:
    prefix = f"[memory] q{question_no}" if question_no else "[memory]"
    print(
        f"{prefix} {job.question_id} retrieved={len(hits)} "
        f"sample={job.sample_id}",
        flush=True,
    )
    for index, item in enumerate(sorted(hits, key=hit_score, reverse=True)[:max_items], 1):
        uri = compact(memory_uri(item), 180)
        memory_type = memory_type_of(item)
        score = hit_score(item)
        preview = compact(memory_content(item), preview_chars)
        print(
            f"[memory]   #{index} score={score:.3f} type={memory_type} uri={uri}",
            flush=True,
        )
        if preview:
            print(f"[memory]      {preview}", flush=True)
这段函数只负责把检索命中的候选记忆转成短日志。它不改排序、不改检索结果、不改模型输入，只是读取已有 hits 并输出摘要。

参考代码 2：插入点

async def answer_question(
    args: argparse.Namespace,
    sdk: Any,
    job: benchmark_adapter.Job,
    out_dir: Path | None = None,
    question_no: int | None = None,
) -> dict[str, str]:
    started = time.time()
    retrieval_error = ""
    query = build_vikingbot_question_prompt(job)
    retrieval_timing = default_retrieval_timing()
    if bool(getattr(args, "qa_memory_injection", True)):
        try:
            hits, retrieval_error, retrieval_timing = await echomemory_retrieve(args, sdk, query)
        except Exception as exc:
            hits = []
            retrieval_error = str(exc)
    else:
        hits = []

    retrieval_completed_ms = ms_since(started)
    segment_raw_started = time.time()
    hits = inject_segment_raw_readback(args, hits)
    segment_raw_readback_ms = ms_since(segment_raw_started)

    log_retrieved_memory_preview(job, hits, question_no=question_no)

    tool_cache: dict[str, dict[str, Any]] = {}
    cache_started = time.time()
    cache_memory_items(tool_cache, hits)
插入点放在 inject_segment_raw_readback() 之后，意味着实时日志里看到的是“最终进入后续处理链的 hits”，比直接打印原始检索结果更接近实际用到的候选记忆。

也就是说，实时日志只是为了“观察当下召回了什么”；真正完整的检索证据仍然保存在 recall JSON 和 CSV 里，方便后续分析。

依赖的辅助函数

memory_uri(item)
抽取 URI，用于日志里定位具体 memory item。
memory_content(item)
抽取 content/text/abstract/overview/summary，作为日志里的 preview 来源。
hit_score(item)
读取检索分数，决定候选记忆排序和日志展示顺序。
memory_type_of(item)
判断是 atom、segment_memory、episode_memory 等，方便在日志里看召回层级。
compact(text, limit)
截断 URI 和内容，避免日志被长路径或长记忆刷爆。

为什么这样放

  1. 不改业务逻辑：只是读取现有 hits，不影响检索、prompt、Tool Calling、判分。
  2. 不改接口：没有新增 API、没有新增 payload 字段、没有新增任务状态结构。
  3. 对实时调试最有用：可以第一时间看出是“没召回到答案附近”，还是“召回了但模型没用上”。
  4. 对通用 EchoMemory QA 自动生效：echomemory_generic_qa.py 复用同一个 answer_question()。

边界说明

  1. 打印的是候选记忆，不是答案。top 5 只是检索命中的候选 evidence，不保证就是最终答案依据。
  2. Tool Calling 可能继续查别的证据。如果启用了工具循环，模型后续还可能通过 memory_search / memory_read_many 拉取额外 memory。
  3. 完整数据仍看 artifact。实时日志适合快速判断召回质量，精确分析仍以 relevant_memory 和 qNNN.recall.json 为准。
