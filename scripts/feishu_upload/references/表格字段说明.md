# 飞书多维表格字段说明

本文件描述飞书多维表格中所有列的定义、数据来源和类型。

字段定义文件：`table_fields.json`
数据提取脚本：`scripts/extract_eval_result.py`

## 飞书字段类型对照

| 类型数字 | 类型名称 | 说明 |
|---|---|---|
| 1 | 文本 | 纯文本字段 |
| 2 | 数字 | 数值字段，需设置 `property.formatter` 为 `0.0000` 以显示 4 位小数 |
| 3 | 单选 | 单选下拉框 |
| 5 | 日期 | 日期字段，值为 Unix 毫秒时间戳 |
| 7 | 复选框 | 布尔值 |
| 17 | 附件 | 文件附件，值为 `[{"file_token": "<token>"}]` |

## 字段清单

共 58 个字段，按功能分组如下。

### A. 标识与元数据

| 列名 | 类型 | 数据来源 | 说明 |
|---|---|---|---|
| 运行ID | 文本(1) | 结果目录名 | 评测运行的时间戳目录名，如 `20260807_173103_910765`，用作查重主键 |
| 运行时间 | 日期(5) | `summary.json` → `run_started_at` | ISO 8601 字符串转为 Unix 毫秒时间戳 |
| 上传人 | 文本(1) | skill 收集 | 上传者姓名，由 skill 向用户收集后合并 |
| 备注 | 文本(1) | `tip.txt`，用户可覆盖 | 评测运行的简短标注（tip.txt），上传时用户可提供自定义内容覆盖 |

### B. 评测配置

| 列名 | 类型 | 数据来源 | 说明 |

## 数据处理规则

1. **Benchmark 组合**：Benchmark 列值为 `<benchmark>-<sample_filter>` 组合格式，如 locomo + conv-30 → `locomo-conv-30`；无样本过滤器时仅 benchmark 名。hotpotqa 的样本过滤器按 question 数量表示：all/0/空 → `hotpotqa`，x 题 → `hotpotqa-x`。
2. **四舍五入**：提取脚本对所有 `float` 类型值执行 `round(val, 4)`，保留 4 位小数。
3. **null 值移除**：上传前移除值为 `null` 的字段，飞书 API 不接受 null。
4. **数字类型**：上传时数字值必须以 JSON number 类型发送（不能是字符串），否则飞书会存为文本，导致 formatter 不生效。
5. **日期格式**：ISO 8601 字符串通过 `_iso_to_ms()` 转为 Unix 毫秒时间戳，飞书日期字段使用此格式。
6. **附件**：由 skill 打包结果目录为 zip，上传到飞书云文档获取 `file_token`，填入附件列。
7. **hotpotqa 指标回填**：hotpotqa 的 `summary.json` 不写 `strict_blackbox.metrics`，提取脚本从 `qa_results.csv` 按 locomo 同款公式聚合：E2E 延迟/检索延迟（ms→s，线性插值分位）、AnswerTokens 平均/P95、请求成功率/失败率/空检索率（按 retrieval/answer/model/health 四状态）、可见模型总Tokens（answer_total_tokens 之和，hotpotqa 无 judge 阶段）、每正确答案Tokens（answer_total_tokens 之和 ÷ answer_em×题目数）、批次耗时（起止时间差）、QA吞吐QPS（题目数 ÷ 批次耗时）。正确数/错误数/准确率/Cat*/JudgeTokens平均 等 locomo 专属字段对 hotpotqa 不输出。
8. **续跑延续**：续跑 run 由 runner 把源运行的原始 `run_started_at` 写入 `resume.original_started_at`（hotpotqa）/ `qa_resume.original_started_at`（locomo）并覆盖 `run_started_at`，批次耗时s / QA吞吐QPS 按「原启动 → 本次结束」计算。仅当原始启动时间不可恢复（源目录已删且无 original_started_at）时置空。
